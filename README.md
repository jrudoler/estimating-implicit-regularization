# Estimating Implicit Regularization in Deep Learning

**[Paper](https://arxiv.org/abs/2605.05436) · [Project page and interactive examples](https://jrudoler.com/estimating-implicit-regularization/)**

Joseph H. Rudoler, Kevin Tan, Giles Hooker, and Konrad P. Kording · University of Pennsylvania

Algorithmic and architectural choices can affect learning much like an explicit regularizer. This project asks whether we can estimate an equivalent regularizer from a trained model or its training updates, and then test whether explicitly applying that regularizer reproduces the original learning procedure.

Given learned weights $\hat\theta$ and a proposed family of penalties $R(\theta;\Lambda)$, we estimate its parameters by matching gradients:

$$
\hat\Lambda = \underset{\Lambda}{\operatorname{argmin}}\;
\left\|\nabla_\theta L(\hat\theta) + \nabla_\theta R(\hat\theta;\Lambda)\right\|_2^2.
$$

At a regularized stationary point, these gradients cancel. A related formulation uses discrepancies between training updates to estimate regularization along a trajectory. The experiments distinguish two validation questions: **can we recover a known regularizer, and does the estimated regularizer reproduce the original model's behavior?** A good gradient fit alone does not guarantee the latter.

The paper tests this approach on explicit elastic-net regularization, early stopping in linear regression, finite-step gradient descent, and dropout in MNIST networks. These provide proof of concept and expose limitations of the proposed penalty families; scaling estimation and validation to larger models remains open.

## Installation

The environment uses **Python 3.12** and **uv** on Linux or macOS. From a fresh checkout:

```bash
git clone --recurse-submodules https://github.com/jrudoler/estimating-implicit-regularization.git
cd estimating-implicit-regularization
bash scripts/bootstrap.sh
```

The bootstrap script installs uv if needed and installs the Python dependencies, including Snakemake. If uv is already installed, you can instead run `uv sync --locked --group dev`.

Run all commands below from the repository root. A CPU is sufficient for the method illustrations and OLS experiments. The neural-network grids are substantially more expensive; a GPU is recommended, and the historical dropout workflow defaults to CUDA. LaTeX is only needed to compile the manuscript.

## Reproducing the experiments

Snakemake connects training, estimation, and plotting. Request a figure to run its upstream experiments and save the resulting PDF under `results/figures/`.

Start with the method illustrations, which require no training or external data:

```bash
uv run snakemake -s workflow/Snakefile --cores 2 results/figures/tradeoff-vis.pdf
```

Then reproduce early stopping in linear regression:

```bash
uv run snakemake -s workflow/Snakefile --cores 4 results/figures/ols_composite.pdf
```

This generates the synthetic data, runs the OLS recovery analyses, and assembles the figure. It requires neither a W&B account nor archived checkpoints.

| Experiment | Figure target under `results/figures/` | Requirements |
| --- | --- | --- |
| Objective and gradient illustrations | `tradeoff-vis.pdf`, `sgd-vs-full-batch.pdf` | CPU; no training |
| Early stopping and quadratic-penalty recovery | `ols_composite.pdf` | CPU; synthetic data generated by the workflow |
| Bootstrap recovery of the OLS regularization matrix | `ols_bootstrap_composite.pdf` | CPU; synthetic data generated by the workflow |
| Explicit elastic-net recovery | `elasticnet_recovery_mean_se.pdf` | Completed W&B sweep or its local results snapshot; see below |
| Finite-step gradient descent | `barrett_igr_figure2.pdf` | MNIST download; neural-network training grid |
| Dropout and scalar ridge estimation | `dropout_bias_ridge_panel.pdf` | Frozen source archive and complete dropout study; see below |
| Dropout checkpoint stability | `dropout_checkpoint_stability_loss_plateau_absolute.pdf` | Dropout study results and retained checkpoints |

For example, to run the gradient-descent experiment on CUDA:

```bash
uv run snakemake -s workflow/Snakefile --cores 1 download_manuscript_mnist
uv run snakemake -s workflow/Snakefile --cores 4 \
  results/figures/barrett_igr_figure2.pdf --config device=cuda
```

That experiment also accepts `device=cpu` or `device=mps`. Download MNIST first as shown above; training then evaluates the widths and learning rates specified in [the training rules](workflow/rules/train.smk).

Add `--dry-run` to any Snakemake command to inspect the jobs before running them. Snakemake reuses existing outputs when they are up to date; deleting outputs or changing dependencies can trigger training again. Always specify a target: the default target builds the manuscript, including its experiment dependencies.

### Explicit elastic-net recovery

The paper's grid has six L1 strengths, six L2 strengths, and ten seeds (360 runs), with smoothing parameter $\beta=10^{-3}$. The configuration is in [elasticnet_sweep_config_beta1e3.yaml](data/provided/sweeps/elasticnet_sweep_config_beta1e3.yaml).

To run a new sweep locally, authenticate with Weights & Biases and replace `YOUR_ENTITY` with your account or team:

```bash
uv run wandb login
uv run wandb sweep --entity YOUR_ENTITY --project inductive-bias \
  data/provided/sweeps/elasticnet_sweep_config_beta1e3.yaml
```

W&B prints a sweep ID and an agent command. Run the agent from the repository root, replacing `SWEEP_ID` with that ID:

```bash
uv run wandb agent YOUR_ENTITY/inductive-bias/SWEEP_ID
```

An agent processes runs until the grid is complete. You can launch additional agents on other devices to share the sweep. Leave `ELASTICNET_FAST` and `ELASTICNET_ULTRA` unset when reproducing the full experiment.

After all runs finish, create `config/sweeps.local.yaml` (ignored by Git):

```yaml
wandb_entity_project: YOUR_ENTITY/inductive-bias
elasticnet_train_and_recover:
  id: SWEEP_ID
```

Then download the completed run summaries and plot them:

```bash
uv run snakemake -s workflow/Snakefile --cores 2 \
  results/figures/elasticnet_recovery_mean_se.pdf
```

The summaries are cached in `data/generated/elasticnet_train_and_recover/runs.parquet`. Plotting uses this snapshot rather than querying W&B on each run. If you already have a completed sweep, start with the local configuration step.

### Dropout: historical reproduction requirements

The manuscript's dropout study trains 480 MNIST networks across depths, widths, dropout probabilities, and seeds. Seven pilot runs establish convergence before the remaining grid runs. This study does not use W&B.

**The full historical study is not reproducible from the Git checkout alone.** Its workflow requires the frozen training-source archive at:

```text
data/generated/dropout_loss_plateau_absolute/source-v1.tar.gz
```

The expected SHA256 is `15fb6023d4d207bf5eafb51e68998958528767a4c74790a57ae7c107ac18e278`. The archive is not included in Git; the workflow verifies it rather than silently substituting current code. Checkpoint audits and matched-replacement experiments also need the retained trajectories and initial states, not just result tables or PDFs.

The workflow stages are:

1. Restore the frozen source and download MNIST.
2. Run `dropout_loss_plateau_pilots` and evaluate the convergence checks.
3. Run `dropout_loss_plateau_full_grid`; nonpilot runs depend on passing the pilot checks.
4. Verify the full grid and generate `results/figures/dropout_bias_ridge_panel.pdf`.
5. Run `matched_dropout_replacement_all` to test explicit replacement, then request `results/data/dropout_matched_replacement.json` to summarize the results.

The archive, checkpoint locations, and storage publisher must be configured for the execution environment before running these targets. In particular, the existing publisher checks filesystem quotas and the audits use recorded checkpoint paths; these parts still require adaptation outside the original environment. See the [dropout study protocol](analysis/dropout_loss_plateau_absolute/README.md) and [matched-replacement protocol](analysis/matched_dropout_replacement/README.md) for convergence criteria and artifact requirements.

### Build all figures or the manuscript

Once the elastic-net results and dropout prerequisites above are available:

```bash
uv run snakemake -s workflow/Snakefile --cores 4 figures
```

To also stage figures into the `paper/` submodule and compile `paper/main.pdf`, install a TeX distribution with `latexmk`, then run:

```bash
uv run snakemake -s workflow/Snakefile --cores 4 paper
```

The manuscript target additionally requires the matched-dropout-replacement summary. Neither command bypasses missing experiment inputs.
